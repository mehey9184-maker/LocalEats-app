## Migration decisions (ADR-013 proposed)
1. Preserve Firebase Auth and FCM browser SDKs; distinguish identity/push from business data. Central API + PostgreSQL authoritative for shop/menu/order/profile; review/favorites and telemetry need explicit data owner and migration. No direct service-role access in frontends. 
2. Start with low-risk fail-closed fixes on exact callsites (false-success and stale heartbeat), tests for no accidental DB writes and UI preservation. Avoid sweeping replacement of shim because account flows depend on it.
3. Prioritize authoritative menu management for vendor pilot; gate writes default-off until database ownership, transaction, validation, idempotency/concurrency and real acceptance proven. Use exact existing design and workflow.
4. Migrate reviews/follows/profile metadata with clear source of truth, verified identities, deduplication and read-only migration rehearsal. Do not discard existing data or claim live rules match source.
5. H2D verify price/consent/GPS/revision contracts; H3 rule/identity/secret audit; H4 network/query budgets; H5 notification reliability. Add H2C.1 focused false-success/heartbeat repair after inventory acceptance, then H2D. No hosted changes, package additions, main merges, live requests or paid services.
