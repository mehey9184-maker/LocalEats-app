## Future native-code policy (proposed, not release work)
Founder wants simple stable fast tasks that rarely change, potentially implemented in C++. Prefer existing TypeScript/SQL/browser-native libraries initially; benchmark real CPU-bound bottlenecks first. Candidate future experiments: pure batch geospatial filtering, offline image transform/thumbnail pipeline, deterministic bulk parsing/packing. Browser/Worker native C++ would need WebAssembly and target-specific tests; native server addon adds ABI/build/deployment cost. I/O, DB queries, network latency, Firebase/FCM and evolving pricing/auth/order workflows are not C++ migration targets by default. Prefer proven library or SQL index/query improvement. Require identical outputs, malformed input bounds, memory safety review, fuzz/sanitizer tests, cross-device/host benchmarks including startup/transfer, fallback, reproducible build and maintenance owner. No code works forever; dependencies, compilers, security and platforms need review. No C++ added, no paid compute and no January-launch dependency.
