## Implemented visual changes
- Welcome: original `LocalEatsLogo`, warm cream background, lightweight embedded local Kota illustration, orange/navy actions. **Explore local food** is first, **Create an account** remains second, **Sign in** third. No fabricated location or account creation.
- Details: visible Step 1 of 2, honest pickup-contact copy, accessible input labels, live email/phone validation, and single *Continue to password* primary action. Google OAuth remains available; the nonfunctional Apple button is removed rather than advertised.
- Password: matching Step 2 of 2 progress, 8-character minimum, clear optional mixed-character suggestion, match feedback, labelled show/hide. The actual Supabase email/password registration and its profile persistence code are unchanged except for the higher local minimum.
- Verification: presents account submission **without claiming an email was always sent or that a customer is verified**. Shows signup email if known, allows **Browse menus for now**, and preserves existing Complete Profile action.
- Home: guest-focused title “Explore local kitchens”, pickup/pay-at-shop subtitle, **real-location needed** banner and explicit **Check location** button when device location unknown; counted records are **shops listed**, not “Online”. Original shop cards, menu, cart, PWA UI, bottom tabs and 4 km pickup restrictions remain.
- Home trust: PR #127’s limited credibility updates are carried onto this separate PR #128-descendant branch where applicable (neutral Shop listing icon, no fabricated rating/verification/prep-time/POPIA claim). No changes to any API/server eligibility or to merchant approval.

## Safe isolated simulation
`tests/signup-home-ux-fixture.tsx` renders **actual production React** Welcome, details, password and verification components, with a fixture-only transition that displays the verification screen **without calling Supabase signup**. Home is represented with the genuine ShopCard and BottomNavigation plus a static representative header, not the entire real HomeScreen (which requires full authenticated app wiring and network). `tests/signup-home-ux-browser.mjs` renders 390x844 and 320x568 Chromium views; blocks all external requests; simulates empty form, invalid email, valid fictional details, password states, a synthetic confirmation transition, and guest-to-Home. GitHub Actions should produce screenshots as an isolated CI artifact; do **not** claim real account creation, actual email delivery, production checkout, real device GPS or entire-app browser acceptance.

## Open technical and release gates
The signup/login screens use **Supabase authentication** while the pickup API expects authenticated **Firebase** identity. This is a separate, critical integration gate before customers may place public pickup orders; design-only changes do not establish compatibility. PR #128 and #127 also have unmerged dependencies and must be reconciled in a separate reviewed integration branch. Confirm CI and real-mobile screenshots before any merge. Pilot ordering remains OFF on Production until separate approval and a genuine consenting customer/shop acceptance. Do not broaden account privileges, weaken policies, enable delivery, make live order/database writes or deploy Production as part of this design phase.
